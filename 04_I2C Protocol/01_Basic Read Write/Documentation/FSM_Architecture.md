# FSM Architecture

## 1. Overview

The I2C Master Controller is implemented using a finite state machine (FSM) to control the sequence of an I2C transaction.

The same FSM supports both:

- Single-byte WRITE
- Single-byte READ

The operation is selected using the `rw` input:

```text
rw = 0 → WRITE
rw = 1 → READ
```

---

## 2. Main FSM Flow

The common transaction flow begins from the IDLE state:

```text
IDLE
  ↓
START
  ↓
SEND_ADDR
  ↓
ADDR_ACK
  ↓
 ┌───────────────┐
 │               │
WRITE           READ
 │               │
 ↓               ↓
WRITE_DATA     READ_DATA
 │               │
 ↓               ↓
WRITE_ACK      READ_ACK/NACK
 │               │
 └───────┬───────┘
         ↓
       STOP
         ↓
       DONE
         ↓
       IDLE
```

---

## 3. IDLE State

The controller remains in IDLE when no transaction is requested.

Typical bus condition:

```text
SCL = HIGH
SDA = HIGH
```

When `start` is asserted, the controller begins a new transaction.

```text
IDLE
  |
  | start = 1
  v
START
```

The controller also clears or initializes the required transaction information.

---

## 4. START State

The START condition is generated by:

```text
SCL = HIGH
SDA: HIGH → LOW
```

This tells the slave that a new I2C transaction is beginning.

After generating START, the controller proceeds to address transmission.

```text
START
  ↓
SEND_ADDR
```

---

## 5. SEND_ADDR State

The master sends the 7-bit slave address followed by the R/W bit.

The transmitted byte is:

```text
{addr[6:0], rw}
```

For the current testbench:

```text
addr = 1010000
```

### WRITE

```text
rw = 0

1010000 + 0
= 10100000
```

### READ

```text
rw = 1

1010000 + 1
= 10100001
```

The address is transmitted MSB first.

A bit counter is used to keep track of the current bit.

---

## 6. ADDR_ACK State

After the 8 address/RW bits have been transmitted, the master releases SDA.

The slave then controls SDA during the ninth clock.

### ACK

```text
SDA = LOW
```

The master continues if ACK is detected.

### NACK

```text
SDA = HIGH
```

The master records an ACK error and terminates the transaction.

Conceptually:

```text
             ┌── ACK ──→ WRITE/READ
             │
ADDR_ACK ────┤
             │
             └── NACK ─→ STOP
```

---

# 7. WRITE Path

If:

```text
rw = 0
```

the controller enters the WRITE path.

```text
ADDR_ACK
   ↓
WRITE_DATA
   ↓
WRITE_ACK
   ↓
STOP
```

## 7.1 WRITE_DATA

The master drives the 8-bit `tx_data` onto SDA.

For example:

```text
tx_data = 10100101
```

Transmission order:

```text
1 → 0 → 1 → 0 → 0 → 1 → 0 → 1
```

The data is transmitted MSB first.

---

## 7.2 WRITE_ACK

After transmitting the eight data bits, the master releases SDA.

The slave generates the ACK.

```text
SDA = LOW → ACK
SDA = HIGH → NACK
```

If the slave ACKs:

```text
WRITE_ACK
    ↓
  STOP
```

If the slave NACKs:

```text
WRITE_ACK
    ↓
ACK ERROR
    ↓
  STOP
```

---

# 8. READ Path

If:

```text
rw = 1
```

the controller enters the READ path.

```text
ADDR_ACK
   ↓
READ_DATA
   ↓
READ_ACK/NACK
   ↓
STOP
```

---

## 8.1 READ_DATA

During READ, the master releases SDA.

The slave becomes the transmitter.

The slave sends eight bits to the master.

For the current testbench:

```text
11001100
```

Transmission order:

```text
1 → 1 → 0 → 0 → 1 → 1 → 0 → 0
```

The master samples SDA while SCL is HIGH.

The received bits are stored in `rx_data`.

---

## 8.2 READ_ACK/NACK

After receiving the final byte, the master sends NACK to indicate that it does not require another byte.

For the current single-byte READ:

```text
READ_DATA
    ↓
Master receives 8 bits
    ↓
Master sends NACK
    ↓
STOP
```

---

# 9. STOP State

The STOP condition is generated by:

```text
SCL = HIGH
SDA: LOW → HIGH
```

This releases the I2C bus.

```text
STOP
  ↓
DONE
```

---

# 10. DONE State

The DONE state indicates that the transaction has completed.

The controller can generate a completion pulse using the `done` output.

The `irq` output in the current implementation also produces a basic completion indication.

After completion:

```text
DONE
  ↓
IDLE
```

---

# 11. Bit Counter

The controller uses a bit counter to control the 8-bit address/data transfers.

For an 8-bit transfer, the bits are processed from:

```text
7 → 6 → 5 → 4 → 3 → 2 → 1 → 0
```

Example:

```text
10100101

bit 7 → 1
bit 6 → 0
bit 5 → 1
bit 4 → 0
bit 3 → 0
bit 2 → 1
bit 1 → 0
bit 0 → 1
```

The bit counter determines when the controller has completed the current byte.

---

# 12. SDA Timing

A key part of the FSM is respecting I2C timing.

During normal data transfer:

```text
SCL LOW
   ↓
Prepare next SDA bit
   ↓
SCL HIGH
   ↓
Receiver samples SDA
```

Therefore, SDA must remain stable throughout the HIGH phase of SCL.

The implementation follows this basic principle for both transmission and reception.

---

# 13. READ vs WRITE

The same `i2c_master.v` handles both operations.

The difference is determined by `rw`.

| `rw` | Operation | Data Direction |
|---:|---|---|
| 0 | WRITE | Master → Slave |
| 1 | READ | Slave → Master |

### WRITE

```text
Master
  |
  | Address + WRITE
  | Data
  v
Slave
```

### READ

```text
Master
  |
  | Address + READ
  v
Slave
  |
  | Data
  v
Master
```

---

# 14. Current FSM States

The current implementation uses states corresponding to the following operations:

| State | Function |
|---|---|
| IDLE | Wait for a new transaction |
| START | Generate START condition |
| SEND_ADDR | Send address + R/W |
| ADDR_ACK | Check slave ACK/NACK |
| WRITE_DATA | Send transmit data |
| WRITE_ACK | Check data ACK/NACK |
| READ_DATA | Receive slave data |
| READ_ACK/NACK | Complete READ acknowledgment |
| STOP | Generate STOP condition |
| DONE | Indicate transaction completion |

The exact state encoding is defined in `i2c_master.v`.

# 16. Future FSM Extensions

The current FSM is intentionally kept simple for the basic READ/WRITE implementation.

Future versions can extend the FSM to support:

- Clock stretching
- Repeated START
- Multi-byte WRITE
- Multi-byte READ
- Arbitration/error handling
- Improved interrupt handling
- Bus recovery

These features will be added progressively while keeping the basic transaction flow as the foundation.

---

## Summary

The FSM provides the control sequence required for a basic I2C Master:

```text
IDLE
 ↓
START
 ↓
SEND ADDRESS
 ↓
ADDRESS ACK
 ↓
 ┌─────────────┐
 │             │
WRITE         READ
 │             │
 ↓             ↓
DATA          DATA
 │             │
ACK          ACK/NACK
 └──────┬──────┘
        ↓
      STOP
        ↓
      DONE
        ↓
      IDLE
```

This FSM forms the foundation for the future I2C features planned for this project.
